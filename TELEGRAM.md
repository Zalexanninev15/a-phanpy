# Telegram в Phanpy

Чтение каналов Telegram в общей ленте рядом с Mastodon-аккаунтами.

## Установка

```sh
npm install teleproto
npm install -D vite-plugin-node-polyfills
npm ci && npm run build
node --test tests/merge-timelines.test.js tests/telegram-adapter.test.js
```

`vite.config.js` в архиве уже содержит блок `nodePolyfills` — он обязателен,
причина ниже.

## Вход

`/telegram/login`. Нужны свои `api_id` и `api_hash` с my.telegram.org
(«API development tools»). Они не зашиты в бандл: общий api_id в публичной
сборке нарушает условия Telegram и отзывается сразу у всех. Хранятся в
localStorage этого устройства.

Дальше телефон → код → при включённой двухэтапной проверке пароль. Сессия
кладётся в localStorage строкой. После входа каналы появляются в `/merged`.

**Риск бана остаётся реальным.** Отдельной кнопки «сделать безопасно» нет.

## Что получилось по весу

| | |
|---|---|
| главный бандл | 413 КБ — не изменился |
| `teleproto` чанк | 84 КБ gzip |
| `sessions` чанк | 425 КБ gzip |

MTProto грузится только при первом обращении к Telegram-сессии. У кого её
нет, тот эти полмегабайта не скачивает никогда.

## Почему понадобились полифилы

`teleproto/crypto/IGE.js` в `encryptIge` вызывает `createCipheriv` из
`node:crypto`, и браузерного фолбэка там нет — в отличие от `decryptIge`, где
чистый JS есть. Шифруется каждое исходящее сообщение, так что без полифила
клиент падает на подключении. Плюс MTProto жмёт крупные ответы, отсюда `zlib`.

Проверено, что `crypto-browserify` даёт бит-в-бит тот же `aes-256-cbc`, что и
`node:crypto`:

```
aes-256-cbc identical: true
sha256 identical: true
```

`fs`, `net`, `vm` намеренно оставлены внешними — их трогают загрузка файлов
на диск, TCP-сокеты и SOCKS-прокси, то есть пути, в браузере недостижимые.

## Ловушка, которая стоила отладки

Первая рабочая версия загрузчика выглядела так:

```js
Promise.all([import('teleproto'), import('teleproto/sessions')])
  .then(([lib, sessions]) => ({ ...lib, ...sessions }))
```

Rolldown не видит сквозь spread namespace-объекта динамического импорта. Он
решил, что результат пуст, свернул всё выражение в `Promise.resolve({})` и
**выбросил teleproto из сборки целиком**. Сборка при этом зелёная, размер
бандла не меняется, ошибка вылезла бы только в рантайме как
«TelegramClient is not a constructor».

Лечится явным перечислением полей — так и сделано, с комментарием в коде,
чтобы не переписали обратно:

```js
const lib = await import('teleproto');
const sessions = await import('teleproto/sessions');
return { TelegramClient: lib.TelegramClient, Api: lib.Api,
         StringSession: sessions.StringSession };
```

Проверять после сборки так:

```sh
grep -rl InvokeWithLayer dist/assets/*.js   # должен что-то найти
```

## Как устроено

`telegram-adapter.js` — чистая функция сообщение→статус. Ни MTProto-типов,
ни сети, ни DOM: на вход обычные объекты той же формы, что отдаёт teleproto.
Поэтому разбор сущностей покрыт тестами — 15 штук, включая случай, где эмодзи
перед жирным текстом сдвигает офсет (Telegram считает в UTF-16, `Array.from`
режет по кодовым точкам).

`telegram-client.js` собирает по источнику на канал и сливает их **тем же**
`createMergedTimeline`, что и Mastodon-ленты. Результат отдаётся наверх как
один источник, поэтому в `/merged` Telegram стоит наравне с аккаунтами, а не
особым случаем. Если сессия битая — источник отваливается молча, ленты
Mastodon продолжают работать.

## Вход без единого Mastodon-аккаунта

Telegram — самостоятельный вход, а не довесок к Mastodon:

- На `/welcome` кнопка «Continue with Telegram» рядом с «Log in with
  Mastodon».
- `/telegram/login` — публичный маршрут. Раньше был обёрнут в `AuthRoute`,
  что требовало Mastodon-авторизации, чтобы попасть на страницу входа —
  логическая ошибка первой версии.
- `/merged` пускает по Mastodon ИЛИ по Telegram (`TelegramOrAuthRoute` в
  `app.jsx`). Без обоих — редирект на `/welcome`, не на `/login`: `/login` —
  это конкретно инстанс-пикер Mastodon, тупик для того, кому нужен только
  Telegram.
- `Root()` в `app.jsx`: без Mastodon-аккаунта, но с Telegram-сессией, корень
  (`/`) показывает `<Merged>` вместо `<Welcome>`.
- В `nav-menu.jsx` пункт Telegram виден и без авторизации. «All accounts»
  теперь появляется и при одном Mastodon-аккаунте, если есть Telegram —
  раньше требовало двух Mastodon-аккаунтов.
- После входа `telegram-login.jsx` уводит туда, откуда пришли (как Mastodon
  OAuth), по умолчанию на `/merged`.

Composer, пуш-уведомления, горячие клавиши, командная палитра остаются
завязаны на `isLoggedIn`, то есть на Mastodon-аккаунт — не трогал: они глубоко
привязаны к текущему Mastodon-аккаунту, переписывать их под Telegram-only —
отдельный, гораздо больший объём работы, никак не связанный с чтением ленты.
Telegram-only пользователь получает ленту, но не композер и не пуши.

## Действия от правильного аккаунта — и что скрыто для Telegram

Каждому Mastodon-посту проставляется `_instance`, `api({ instance })` находит
по нему аккаунт — ответ, буст и избранное уходят от нужного пользователя.

Telegram-постам вместо этого стоит `_readonly: true`, и в
`src/components/status.jsx` блок кнопок действий целиком скрыт:

```jsx
{status._readonly ? null : (
  <div class={`actions ...`}>...</div>
)}
```

Это тот самый компонент, про который я раньше написал, что не трогал его и
оставил решение за вами — неточность в отчёте: правка на тот момент уже стояла
в коде. Сейчас код и описание сверены заново.

## Что не проверено

Ни одна строчка ниже не открывала сокет. Окружение, где это писалось, не
имеет доступа к дата-центрам Telegram, поэтому формы запросов, автомат входа
и загрузка медиа выведены из API библиотеки, а не наблюдались:

- `client.start()` и порядок колбэков кода и пароля 2FA
- `getDialogs` → фильтр `isChannel && !isGroup`
- `getMessages` с `offsetId` для пагинации
- `downloadMedia(message, { thumb: -1 })` и blob-URL

Плюс весь новый роутинг (`Root()`, `TelegramOrAuthRoute`, кнопка на
`/welcome`) — это JSX и переходы между страницами, не покрытые
`node --test`: юнит-тесты проверяют только чистую логику (слияние лент,
разбор сущностей), а не рендер и не React Router. Собирается и проходит все
guard'ы в CI, но реальных кликов по кнопкам никто не делал.

Первое, что стоит проверить руками: приходят ли каналы после входа, и
работает ли переход `/welcome` → «Continue with Telegram» → вход → `/merged`
от начала до конца на настоящем аккаунте.

## Известные ограничения

- Лента read-only: реакции, просмотры и атрибуция пересылок отброшены, а не
  подделаны; кнопки действий на Telegram-постах скрыты (см. выше).
- Медиа тянется в полный размер превью и живёт в памяти до выхода. Кэша в
  IndexedDB нет, при долгой прокрутке память будет расти.
- Альбом сворачивается в один пост по первому сообщению группы; остальные
  картинки альбома не показываются.
- Аватарки каналов не загружаются — это отдельный `downloadProfilePhoto`.
- «Проверка новых постов» (pull-to-refresh индикатор) на `/merged` спрашивает
  только Mastodon-аккаунты. Для Telegram-only пользователя индикатор новых
  постов работать не будет — сама лента при этом обновляется как обычно,
  просто без подсказки «есть новое».
- Заголовок `/merged` всегда «All accounts», даже когда Mastodon-аккаунтов
  нет и это по факту только Telegram. Косметика, меняется одной строкой в
  `merged.jsx`.
- `isRootPath()` в `app.jsx` (список путей вроде `/login`, `/welcome`,
  участвующий в анимации переходов) я не расширял на `/telegram/login` —
  не было ясного повода трогать малопонятный мне механизм. Если переход
  с `/welcome` на `/telegram/login` будет визуально дёргаться иначе, чем
  переход на `/login`, скорее всего дело в этом.
